# ReCodera-AI Community Edition v2026.11.15.01

## Summary of Changes

This Pull Request provides a comprehensive, production-grade resolution for long-standing bidirectional (BiDi) and Right-to-Left (RTL) editing issues in Notepad++, delivering native-quality rendering for Arabic, Hebrew, and Persian mixed with English text and source code.

The changes address rendering consistency across both **DirectWrite** and **GDI** backends, eliminate visual artifacts, ensure full session persistence for document direction, and prevent UI regressions.

---

## Key Problems Solved & Technical Details

### 1. Mixed Arabic and English Text in LTR Documents
- **Issue**: In LTR mode, mixed lines with Arabic comments and English code suffered from measurement inaccuracies and caret drift.
- **Solution**: Enhanced Scintilla's `PositionCache` and `BreakFinder` with `splitDirectional` logic. It automatically detects directional transitions (`IsRTLChar` for Unicode UTF-8 and Windows-1256) and splits them into distinct segments, ensuring precise measurement and caret placement.

### 2. Seamless Dynamic Technology Switching (DirectWrite <-> GDI)
- **Issue**: DirectWrite rendering targets are incompatible with Windows `WS_EX_LAYOUTRTL` mirroring, which previously prompted a modal message box requiring the user to disable DirectWrite in Preferences and restart Notepad++.
- **Solution**: Replaced the modal warning in `ScintillaEditView::changeTextDirection` with an automatic, dynamic switch to GDI default technology when entering RTL mode, and restored the user's preferred DirectWrite engine seamlessly when toggling back to LTR.

### 3. DirectWrite Full Visual Layout Rendering (`SurfaceD2D::DrawLayout`)
- **Issue**: Drawing individual style segments piecemeal through DirectWrite led to redundant wrapping and disrupted BiDi shaping.
- **Solution**: Implemented `SurfaceD2D::DrawLayout` using `IDWriteTextLayout` with `DWRITE_WORD_WRAPPING_NO_WRAP` and `PushAxisAlignedClip`, enabling cohesive line drawing while preserving hardware acceleration in LTR mode.

### 4. Per-Document RTL State Persistence
- **Issue**: RTL document state was transient and lost when switching tabs or closing the editor.
- **Solution**: Added `<RTLFiles>` serialization to `session.xml` via `NppParameters` (`feedRTLFilesParameters`, `writeRTLFilesSettings`, `setFileRTL`, `isFileRTL`), automatically synchronizing and restoring direction on `activateBuffer`.

### 5. Uniscribe Bidirectional Reordering in RTL Mode (`ScreenLineLayoutGDI`)
- **Issue**: In RTL mode under GDI, English multi-word phrases and code snippets inside Arabic sentences had their word order reversed.
- **Solution**: Implemented `ScreenLineLayoutGDI` using Uniscribe (`ScriptItemize`, `ScriptLayout`). Pure-LTR lines remain unified at `level = 0` to prevent leading bullets or punctuation from detaching, while mixed lines resolve English runs to even levels (`level = 2` or `0`), maintaining natural LTR word order within right-aligned paragraphs.

### 6. Parentheses, Brackets, and Directional Mirroring
- **Issue**: Parentheses enclosing LTR phrases often curled in the same direction or mirrored inverted (e.g., `Merge Resolution((`).
- **Solution**:
  - Confined unclosed parenthesis tracking to the scope of the immediate LTR run, preventing Arabic punctuation from corrupting the run boundary.
  - Wrapped resolved RTL runs with `RLM` (`U+200F`) to trigger proper Unicode Rule L4 bracket mirroring in GDI, and wrapped LTR runs with `LRM` (`U+200E`) to protect internal punctuation.

### 7. Code Identifier Integrity (`_rtlFiles`) & Range Dashes (`1763–1777`)
- **Leading Underscores**: Added prefix reattachment in `ScreenLineLayoutGDI` to keep leading underscores attached to the left of ASCII identifiers (e.g., preserving `_rtlFiles` rather than displaying `rtlFiles_`).
- **Numeric Ranges**: Promoted isolated range dashes flanked by even-level runs to LTR, preventing sequential numbers and line ranges from inverting (e.g., `1763–1777` remains ascending).

### 8. Trailing Background Gap Elimination (`rcGap`)
- **Issue**: Differences between visual width (`visualRight`) and logical width (`logicalRight`) left unpainted rectangular black or mismatched gaps at line ends in RTL mode.
- **Solution**: Implemented `rcGap` detection and filled trailing intervals with the exact background color and selection state using `TextBackground()`.

### 9. Upstream Master Synchronization (Scintilla 5.6.8 & Lexilla 5.5.5)
- Fully rebased and cleanly merged with upstream `notepad-plus-plus:master`.
- Resolved merge conflict in `scintilla/win32/ScintillaWin.cxx` (`Message::SetBidirectional`): adopted upstream's new `SetAppearance` mechanism for style invalidation while preserving BiDi activation on both GDI (`Technology::Default`) and DirectWrite backends.
- Verified coexistence with Lexilla 5.5.5, Malayalam translations, and modern dialog layouts with zero regressions.
